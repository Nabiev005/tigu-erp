# ТигүүERP

Тигүү цехтери (10–200 кызматкер) үчүн ERP/MES система: буйрутма → тех. карта → кесүү жана QR-коддуу пачкалар → операцияларды сканерлөө → сдельный эмгек акы жана буйрутманын даярдыгы.

## Талаптар

- Node.js 20.11+ (`.nvmrc`)
- pnpm 9 (`corepack enable` же `npm i -g pnpm@9`)
- Docker **керек эмес**: PostgreSQL 16 `node_modules` ичинен [embedded-postgres](https://github.com/leinelissen/embedded-postgres) аркылуу ишке кирет.

## Тез баштоо

```bash
pnpm install
cp .env.example .env      # керек болсо порттарды өзгөртүңүз
pnpm dev                  # биринчи жолу: база түзүлүп, миграциялар колдонулат
pnpm db:seed              # башка терминалда: «Демо цех» жана демо-колдонуучулар
```

`pnpm dev` төмөнкүлөрдү бирге ишке киргизет:

| Процесс                  | Дарек                                                                      |
| ------------------------ | -------------------------------------------------------------------------- |
| PostgreSQL 16 (embedded) | `localhost:5433` (маалымат `apps/api/.data/postgres` ичинде)               |
| API (Fastify)            | http://localhost:3000 — `GET /health`, `GET /ready`                        |
| Web (Vite)               | http://localhost:5173 — `/api`, `/health`, `/ready` сурамдарын APIге берет |

Биринчи ишке киргизгенде embedded-postgres кластерди түзүп, `tigu` базасын ачат (бир нече секунд).

Текшерүү:

```bash
curl http://localhost:3000/health   # {"status":"ok"}
curl http://localhost:3000/ready    # {"status":"ok","checks":[{"name":"postgres","ok":true}]}
```

## Коопсуздук: tenant изоляциясы

Ар бир ишкананын маалыматы эки катмар менен бөлүнөт (ТТ §13):

1. **Prisma extension** (`apps/api/src/lib/db.ts`) ар бир суроого `tenantId` шартын кошот, ал эми `create` учурунда `tenantId`'ди коёт. `tenantId` дайыма JWT'ден алынат.
2. **PostgreSQL RLS.** API `tigu_app` ролу менен туташат (ал таблицалардын ээси эмес, ошондуктан RLS ага колдонулат). Ар бир суроо транзакциянын ичинде `app.tenant_id`'ди коёт, жана саясаттар башка ишкананын саптарын көрсөтпөйт. Бул SQL'де `WHERE` унутулуп калса да иштейт.

Миграциялар таблицалардын ээси (`tigu`) катары колдонулат. Ролду түзүү жана grant'тар `apps/api/scripts/db-setup.ts` скриптинде.

## Тесттер

`pnpm test` интеграциялык тесттер үчүн өзүнчө PostgreSQL ишке киргизет (5439-порт, убактылуу папка) жана тесттер бүткөндө аны өчүрөт. Иштеп чыгуу базасына тийбейт.

## MSW (жасалма API)

Браузерде MSW **бэкендде али жок** endpoint'терге гана жооп берет (азыр: моделдер, 3-этап). Auth, колдонуучулар жана жөндөөлөр чыныгы API аркылуу иштейт. UI тесттери бэкендсиз иштеши үчүн толук MSW handler'лерин колдонот.

## Баштапкы ТТдан айырмасы (Docker'сиз)

| ТТда                 | Азыр                                                                 | Себеби                                                      |
| -------------------- | -------------------------------------------------------------------- | ----------------------------------------------------------- |

| MinIO (S3)           | `STORAGE_DIR` локалдуу папкасы, `StorageProvider` интерфейси аркылуу | Продакшнда S3 туташтырылат                                  |
